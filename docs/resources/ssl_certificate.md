# mtncloud_ssl_certificate

An SSL certificate you upload: a certificate and its private key, for load balancers and apps. MTN Cloud never returns the certificate or key, so changes to them made in the console aren't seen.

## Example Usage

```terraform
variable "shop_key" {
  type      = string
  sensitive = true
}

resource "mtncloud_ssl_certificate" "shop" {
  name                = "shop-example-com"
  description         = "Storefront certificate"
  domain_name         = "shop.example.com"
  certificate         = file("${path.module}/shop.crt")
  chain               = file("${path.module}/chain.crt")
  private_key         = var.shop_key
  private_key_version = 1 # change it, with the new key, to send the key again
}
```

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `certificate` (String) The certificate, PEM-encoded. Changing it uploads it again in place; a new certificate usually needs its new key too, so change `private_key_version` with it.
- `name` (String) Certificate name.
- `private_key` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The private key, PEM-encoded. Write-only (Terraform 1.11 or newer): never stored. To send a new key, change `private_key_version`.

### Optional

- `chain` (String) Intermediate certificates, PEM-encoded.
- `description` (String) Description.
- `domain_name` (String) Domain name the certificate is for.
- `private_key_version` (Number) Any number; changing it sends `private_key` again. Write-only values can't be compared, so this is how a new key is noticed.
- `wildcard` (Boolean) Whether it is a wildcard certificate. Defaults to `false`.

### Read-Only

- `common_name` (String) Common name (CN), as MTN Cloud reads it from the certificate.
- `id` (String) Certificate ID.
- `self_signed` (Boolean) Whether the certificate is self-signed.

## Import

Import is supported using the following syntax:

```shell
# Imported by its numeric ID (Infrastructure > Keys & Certs > SSL Certificates).
terraform import mtncloud_ssl_certificate.shop 42
```

MTN Cloud doesn't return the certificate, chain or key, so they come from your configuration. The first
apply after an import records them and sends nothing.

## Notes

- Only certificates you upload can be managed. Certificate requests and generated certificates can be
  read with the `mtncloud_ssl_certificate` data source.
- The private key is write-only (Terraform 1.11 or newer): it is never stored in state or plans. It is
  sent on create, and again whenever `private_key_version` changes.
- Names aren't unique in MTN Cloud, so create refuses a name that already exists and asks you to import it.
