# mtncloud_self_managed_kubernetes

A self-managed Kubernetes cluster: MTN Cloud builds it, and you run and maintain it. Ordered from MTN Cloud's catalog (MTN KUBERNETES (MK8S)). The order's inputs can't be changed afterwards (replace it with `terraform apply -replace=<address>`). `terraform destroy` deletes what it made, shown under Apps in the console, with its disks and floating IPs, then the order's record in Catalog > Inventory. Secrets are write-only (Terraform 1.11 or newer): they are sent with the order and never stored.

## Example Usage

```terraform
resource "mtncloud_self_managed_kubernetes" "k8s" {
  name                    = "apps-k8s"
  project                 = "web-prod"
  master_plan             = "G2S4"
  master_root_volume_size = 50
  master_networks         = ["app-net"]
  master_security_groups  = ["web"]
  master_count            = 3
  worker_plan             = "G4S16"
  worker_root_volume_size = 100
  worker_networks         = ["app-net"]
  worker_security_groups  = ["web"]
  worker_count            = 3
  cni                     = "calico"
}
```

## Import

Import is supported using the following syntax:

```shell
# Imported by the ID of its catalog order (Catalog > Inventory).
terraform import mtncloud_self_managed_kubernetes.k8s 9801
```

The order doesn't show what it was placed with, so the inputs come from your configuration: write them
exactly as ordered. The first apply after an import records them, finds the instances by name, and orders nothing.

## Notes

- **Self-managed.** MTN Cloud builds the cluster (masters, workers, the CNI you pick); after that,
  upgrades, add-ons and day-to-day running are yours.
- **Renamed from `mtncloud_managed_kubernetes`** (0.6.0). The old name still works for now, with a
  deprecation warning. To switch without replacing anything, rename the resource and add:

  ```terraform
  moved {
    from = mtncloud_managed_kubernetes.k8s
    to   = mtncloud_self_managed_kubernetes.k8s
  }
  ```

  `moved` between resource types needs Terraform 1.8 or newer. On older versions, take it out of state
  and import it under the new name, by its order ID (Catalog > Inventory). The first apply after the
  import records the inputs and orders nothing:

  ```shell
  terraform state rm mtncloud_managed_kubernetes.k8s
  terraform import mtncloud_self_managed_kubernetes.k8s <order id>
  ```
- **An order, not a live object.** Create places the catalog order and waits for MTN's workflow to
  finish, then finds the instances it made by `name` in the project (`instance_ids`). The inputs
  can't be changed afterwards: the plan refuses, so nothing is ever ordered twice by accident.
- **Destroy deletes what the order made.** Its instances are deleted with their disks and floating
  IPs, then the order's record in Catalog > Inventory. The cluster is an app (under Apps in the
  console), so its app is deleted with all its instances. Another app is deleted only if it holds
  nothing but this order's instances; otherwise only the order's instances leave it. Destroy waits
  until they are gone (`timeouts { delete }`, default 90 minutes). It refuses, deleting nothing, while
  the order's workflow still runs past the timeout, after an import that hasn't been applied, or when
  nothing the order made can be found. To keep what it made, use a `removed` block
  (`lifecycle { destroy = false }`) or `terraform state rm` instead. If everything it made is
  deleted outside Terraform, the next plan orders it again.
- **Secrets are write-only** (Terraform 1.11 or newer): they are sent with the order and never stored
  in state or plans.
- **Names are checked when you plan**: project, plan, networks, security groups, floating IP pool,
  environment and every choice list (versions and so on) are looked up in MTN Cloud before anything
  is ordered, and an unknown value lists the valid ones. A floating IP pool must also be the external
  network of the router that holds the first network: another pool is an error, and no router a warning.
- **A failed workflow** is reported with MTN Cloud's message and nothing is kept; delete whatever it
  left in the console before applying again.
