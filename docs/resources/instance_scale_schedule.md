# mtncloud_instance_scale_schedule

Applies a library scale threshold (`mtncloud_scale_threshold`) to an instance for part of the week, or between two dates. While the schedule is on, its threshold replaces the instance's own scaling (the `scale` block). MTN Cloud copies the threshold's values into the schedule: when the threshold changes, the next plan shows `scale_threshold_id` set again, and applying copies the new values.

## Example Usage

```terraform
# A library threshold for office hours: up to 4 servers when CPU runs hot.
resource "mtncloud_scale_threshold" "office_hours" {
  name                 = "office-hours"
  auto_upscale         = true
  auto_downscale       = true
  min_count            = 1
  max_count            = 4
  enable_cpu_threshold = true
  min_cpu_percentage   = 20
  max_cpu_percentage   = 75
}

# Apply it to the web VM from Monday 08:00 to Friday 18:00, Lagos time.
resource "mtncloud_instance_scale_schedule" "web_weekdays" {
  instance_id        = mtncloud_instance.web.id
  scale_threshold_id = mtncloud_scale_threshold.office_hours.id
  time_zone          = "Africa/Lagos"
  start_day          = "monday"
  start_time         = "08:00"
  end_day            = "friday"
  end_time           = "18:00"

  # Copy a changed threshold in the same apply, by making the schedule again.
  lifecycle {
    replace_triggered_by = [mtncloud_scale_threshold.office_hours]
  }
}

# A one-off window, with the same threshold.
resource "mtncloud_instance_scale_schedule" "web_sale" {
  instance_id        = mtncloud_instance.web.id
  scale_threshold_id = mtncloud_scale_threshold.office_hours.id
  start_date         = "2026-11-27T00:00:00+01:00"
  end_date           = "2026-11-30T23:59:00+01:00"

  lifecycle {
    replace_triggered_by = [mtncloud_scale_threshold.office_hours]
  }
}
```

## Notes

- **The values are copied.** MTN Cloud copies the library threshold's values into the schedule when it is made
  or updated, and keeps no link to the threshold. The `threshold` attribute shows the copy.
- **When the threshold changes,** the schedule keeps the old values until the next apply: the plan after the
  change shows `scale_threshold_id` being set again, and applying copies the new values. To copy them in the
  same apply that changes the threshold, add `replace_triggered_by = [mtncloud_scale_threshold.<name>]` to
  the schedule's `lifecycle` block, as in the example. A threshold that is deleted shows the same way, and
  applying fails until `scale_threshold_id` names one that exists.
- **Weekly or once.** Give `start_day`, `start_time`, `end_day` and `end_time` for a weekly window (in
  `time_zone`, UTC by default), or `start_date` and `end_date` for one window.
- **A retried create doesn't add a second schedule.** Create takes over a schedule on the instance only when its
  times, time zone and copied values all match; schedules have no name, so any other schedule is left alone.
- **The instance's own scaling** (the `scale` block on `mtncloud_instance` or `mtncloud_instance_settings`)
  applies outside the schedule's window.

## Schema

### Required

- `instance_id` (String) ID of the instance, for example `mtncloud_instance.web.id`. Changing it makes a new schedule.
- `scale_threshold_id` (String) ID of the library threshold to apply, for example `mtncloud_scale_threshold.busy.id`. Changing it copies the new threshold's values in place.

### Optional

- `end_date` (String) Moment the schedule turns off, in RFC 3339 form.
- `end_day` (String) Day the schedule turns off each week, `sunday` to `saturday`.
- `end_time` (String) Time on `end_day` the schedule turns off, 24-hour `HH:MM`.
- `start_date` (String) Moment the schedule turns on, once, in RFC 3339 form, for example `2026-12-24T00:00:00Z`. Give it with `end_date`, instead of the weekly days and times.
- `start_day` (String) Day the schedule turns on each week, in lower case: `sunday` to `saturday`. Give it with `start_time`, `end_day` and `end_time`, or give `start_date` and `end_date` instead.
- `start_time` (String) Time on `start_day` the schedule turns on, 24-hour `HH:MM`.
- `time_zone` (String) Time zone of `start_time` and `end_time`, for example `Africa/Lagos`. Defaults to `UTC`. Only with `start_day`.

### Read-Only

- `id` (String) `<instance_id>/<schedule_id>`.
- `threshold` (Attributes) The values copied from the library threshold, as MTN Cloud holds them. (see [below for nested schema](#nestedatt--threshold))

- `min_memory_percentage` (Number) Low memory mark, in percent; null when not watched.

## Import

Import is supported using the following syntax:

```shell
# By <instance_id>/<schedule_id>. A schedule doesn't record which threshold it was copied from, so the
# first plan after an import sets scale_threshold_id, and applying copies that threshold's values in.
terraform import mtncloud_instance_scale_schedule.web_weekdays 4650/3
```
