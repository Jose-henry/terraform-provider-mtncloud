# mtncloud_power_schedule

A weekly power schedule: the hours each day that instances on it run. MTN Cloud stops them at the off time and starts them at the on time. Put instances on it with `mtncloud_instance_power_schedule`. A schedule an instance is still on can't be deleted, so destroy the attachments first (Terraform does when they reference the schedule).

## Example Usage

```terraform
# Office hours: weekdays 07:00 to 19:30 Lagos time, off at the weekend.
# Days left out (here none) run all day.
resource "mtncloud_power_schedule" "office_hours" {
  name        = "office-hours"
  description = "Dev VMs: weekdays only"
  time_zone   = "Africa/Lagos"

  monday    = { on = "07:00", off = "19:30" }
  tuesday   = { on = "07:00", off = "19:30" }
  wednesday = { on = "07:00", off = "19:30" }
  thursday  = { on = "07:00", off = "19:30" }
  friday    = { on = "07:00", off = "19:30" }
  saturday  = { on = "00:00", off = "00:00" } # off all day
  sunday    = { on = "00:00", off = "00:00" }
}

# Only stops VMs late at night; people start them again when they need them.
resource "mtncloud_power_schedule" "nightly_stop" {
  name      = "nightly-stop"
  time_zone = "Africa/Lagos"
  stop_only = true

  monday    = { on = "00:00", off = "22:00" }
  tuesday   = { on = "00:00", off = "22:00" }
  wednesday = { on = "00:00", off = "22:00" }
  thursday  = { on = "00:00", off = "22:00" }
  friday    = { on = "00:00", off = "22:00" }
}
```

## Notes

- **Days you leave out run all day** (00:00 to 24:00), as in the console. To keep instances off for a whole
  day, give `{ on = "00:00", off = "00:00" }`. Writing `{ on = "00:00", off = "24:00" }` is refused: leave the day out.
- **Times** are 24-hour `HH:MM` in `time_zone`; minutes are kept. `off` can't be before `on` (checked at plan time).
- **`stop_only = true`** only stops instances at the off times; nothing starts them at the on times.
- **Deleting a schedule an instance is on is refused** by MTN Cloud. Terraform destroys the
  `mtncloud_instance_power_schedule` attachments first when they reference the schedule; one made in the console
  must be removed there first.
- **Names must be new.** Schedule names aren't unique on MTN Cloud, so a create that finds one with the same name
  stops and gives its ID: import it to manage it here, or choose another name. A create retried after a timeout
  says the same, with the ID it made.
- **`time_zone`** is checked at plan time against the IANA names (case matters), since MTN Cloud stores any text.
- To look up a schedule made in the console, use the `mtncloud_power_schedule` data source.
