# mtncloud_project

An MTN Cloud project, ordered from the catalog ("Create Project"). Creating it waits for the order's workflow to finish, not for the project to sync in: its default security group, networks and floating IP pools can take up to an hour to appear. A project can't be renamed or deleted from Terraform.

## Example Usage

```terraform
# Orders MTN's "Create Project" catalog item. MTN Cloud names it "web-prod-<tenant>".
resource "mtncloud_project" "web" {
  name        = "web-prod"
  description = "Web tier, production"
}
```

## Schema

### Required

- `name` (String) Project name: a lowercase letter, then lowercase letters, digits, `_` or `-`. MTN Cloud adds your tenant name (see `full_name`). It can't be changed after the order.

### Optional

- `description` (String) Description of the project. It can't be changed after the order.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `full_name` (String) The name MTN Cloud gives the project, `<name>-<tenant>`. Other resources accept either name in their `project` argument.
- `id` (String) ID of the catalog order item (Catalog > Inventory in the console). Used to import the project.
- `status` (String) Status of the order's workflow, for example `success`.

## Import

Import is supported using the following syntax:

```shell
# A project is imported by its catalog order ID (Catalog > Inventory in the console).
terraform import mtncloud_project.web 9801
```

The order doesn't show the name and description it was placed with, so they come from your
configuration: write them exactly as ordered. The first apply after an import records them and sends
nothing.

## Notes

- **Waits for the order only.** Create places the order and waits for MTN's "Create Project"
  workflow to finish (default timeout 15 minutes, see `timeouts`). It does not wait for the project
  to sync in. Allow **up to an hour** before its default security group, networks and floating IP
  pools are all there.
- **Use it in a later apply.** Other resources look their `project` up by name when they plan, so
  they can't name a project ordered in the same apply. Apply the project first, give it time to
  sync, then add the resources that use it.
- **A failed workflow** is reported with MTN Cloud's message and nothing is kept, so the next apply
  orders again. If the workflow's result isn't known when the timeout ends, the order is kept with a
  warning and is never placed twice; a later refresh that finds it failed drops it, so the next apply
  orders again.
- **Can't change.** `name` and `description` are fixed when the order is placed. A change is refused
  at plan time, so a second project is never ordered by accident.
- **Can't be deleted from Terraform.** MTN Cloud has no order that deletes a project, so
  `terraform destroy` stops with an error. To stop managing a project and keep it, use a `removed`
  block (Terraform 1.7 or later) or `terraform state rm`. To delete the project itself, ask MTN Cloud
  support.

```terraform
removed {
  from = mtncloud_project.web
  lifecycle {
    destroy = false
  }
}
```

- **Names.** A lowercase letter, then lowercase letters, digits, `_` or `-`, checked at plan time. The
  name of a project that has synced is refused at plan time; an order still running isn't visible
  yet, so if an apply fails with "the order may have been placed", check Catalog > Inventory and
  import it before applying again.
