# mtncloud_security_group_rule

One rule of a security group, for rules managed apart from the group (for example from another module). Leave `rules` unset on that `mtncloud_security_group`: using both on one group makes them undo each other. Every change replaces the rule.

## Example Usage

```terraform
# A group whose rules are managed one by one: leave "rules" unset on it.
resource "mtncloud_security_group" "app" {
  name    = "app"
  project = "web-prod"
}

resource "mtncloud_security_group_rule" "http" {
  security_group_id = mtncloud_security_group.app.id
  direction         = "ingress"
  protocol          = "tcp"
  port_range        = "8000-8080"
  cidr              = "10.0.0.0/24"
  description       = "app ports"
}
```

## Schema

### Required

- `direction` (String) `ingress` (traffic to the instances) or `egress` (traffic from them).
- `protocol` (String) `tcp`, `udp`, `icmp` or `any`.
- `security_group_id` (String) The security group (its `id`) the rule belongs to.

### Optional

- `cidr` (String) The remote addresses, written as a network (`"10.0.0.0/24"`, `"0.0.0.0/0"`): where traffic comes from for `ingress`, where it goes for `egress`. Leave it and `source_security_group_id` out to allow any address.
- `description` (String) A short note shown in the console. Changing it recreates the rule: it is removed, then added again, so its traffic is briefly blocked.
- `port_range` (String) A port (`"22"`) or a range (`"8000-8080"`), for `tcp` and `udp`. Leave it out to allow every port.
- `source_security_group_id` (String) Allow the instances in this security group (its `id`) instead of a CIDR.

### Read-Only

- `id` (String) `<security group id>/<rule id>`.
- `rule_id` (String) Rule ID.

## Import

Import is supported using the following syntax:

```shell
# <security group id>/<rule id>
terraform import mtncloud_security_group_rule.http 9501/9701
```
