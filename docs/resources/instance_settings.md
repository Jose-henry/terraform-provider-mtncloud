# mtncloud_instance_settings

Day-2 settings of an instance this configuration doesn't own: a catalog order's VM, a managed service's or app's, or one made in the console. Create adopts the instance by `instance_id` and changes only the settings you set; settings you leave out aren't managed and show the VM's own values. **Destroy leaves the VM**: it only stops managing these settings (delete the VM through whatever owns it). An instance with several servers takes each setting on every server. The VM's image, project, networks, root disk and name can't change here: changing them would rebuild it. Manage an instance with either `mtncloud_instance` or this resource, never both.

## Example Usage

```terraform
variable "db_password" {
  type      = string
  sensitive = true
}

# A database VM made by a catalog order: the order owns it, these settings manage it day to day.
resource "mtncloud_mysql" "db" {
  name              = "db-1"
  project           = "web-prod"
  plan              = "G2S4"
  root_volume_size  = 40
  networks          = ["app-net"]
  version           = "8.4"
  database_name     = "shop"
  database_user     = "shop"
  database_password = var.db_password
}

resource "mtncloud_instance_settings" "db" {
  instance_id     = mtncloud_mysql.db.instance_ids[0]
  plan            = "G4S8" # resizes in place, and restarts the VM
  security_groups = ["web"]
  labels          = ["shop", "database"]
  power_state     = "running"
}
```

## Notes

- **Ownership.** The order, app or console that made the VM still owns it: destroying that deletes the
  VM, and these settings leave state on the next refresh. Don't manage one instance with both
  `mtncloud_instance` and this resource.
- **Resize restarts.** Changing `plan` restarts the VM. MTN's catalog workflows don't reset a changed
  plan or other settings.
- **Settings left out** aren't managed: they show the VM's values, and removing one from the
  configuration leaves the VM as it is.
- **Disks.** With `data_volume` blocks, list the VM's data disks first (an order may add its own), then
  new ones. New disks attach in place; a disk can't be changed or removed here.
- **Floating IP.** `floating_ip_pool` attaches one address per server. An address released in the console
  is attached again by the next apply; removing the argument keeps the address.
- **Scaling.** `scale` is read back only while it is set: removing it leaves the VM's scaling as it is.
- **Timeouts:** `create` and `update`, 30 minutes by default; a resize waits within them.

## Schema

### Required

- `instance_id` (String) ID of the instance, for example a catalog order's `instance_ids[0]`. Changing it adopts another instance.

### Optional

- `data_volume` (Block List) The instance's data disks (not the root disk), in order. With none, disks aren't managed. With some, they must start with the disks the instance has (the `mtncloud_instance` data source lists them), and disks added at the end are attached in place. A disk can't be changed or removed here. (see [below for nested schema](#nestedblock--data_volume))
- `description` (String) Description shown in the console. Changed in place.
- `floating_ip_pool` (String) Give the instance a floating (public) IP from this pool, for example `public-network-02`, one per server. An address it already has is kept. Changing the pool releases the old addresses and attaches new ones; an address released in the console is attached again. Left out, floating IPs aren't managed (removing it keeps the address). Needs the instance's network to be on an MTN Router with an external network.
- `labels` (Set of String) Labels. Set, they replace the instance's labels in place; `[]` clears them.
- `plan` (String) Plan (size) by name, for example `G2S4`. Changing it resizes the instance in place and **restarts it**; the root disk keeps its size. Left out, the plan isn't managed.
- `power_state` (String) `running`, `stopped` or `suspended`. Set, the VM is powered to it in place, and put back by the next apply when changed in the console. A plan change restarts the VM, then it is put back in this state. **`suspended` doesn't work on MTN Cloud's images so far** (tried on Ubuntu 24.04 and Debian 12): MTN Cloud accepts it but the VM keeps running, and the apply fails after 2 minutes. Use `stopped`.
- `restart_trigger` (String) Any value. Changing it restarts a running VM in place, for example after a config change. Setting it the first time (at create, after an import, or added later) doesn't restart.
- `scale` (Attributes) Automatic scaling: MTN Cloud adds a VM when usage stays above a metric's `max` and removes one below its `min`, between `min_count` and `max_count`. Watch at least one of `cpu`, `memory`, `disk`. Changed in place, and put back when changed in the console. Left out, scaling isn't managed (and isn't shown); removing it leaves scaling as it is. (see [below for nested schema](#nestedatt--scale))
- `security_groups` (Set of String) Security groups by name, in the instance's project, in addition to the project's default group, which is always applied. Set, they replace the instance's other groups in place.
- `tags` (Map of String) Tags. Set, they replace the instance's tags in place; `{}` clears them.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `expire_date` (String) When the instance will be deleted, if it expires (set when it was made, or by a policy). Read only.
- `group` (String) The instance's group (availability zone), read only.
- `id` (String) The instance's ID.
- `image` (String) The instance's image, read only.
- `name` (String) The instance's name, read only.
- `private_ip` (String) The instance's private address.
- `public_ip` (String) The instance's floating IP, when it has one.
- `public_ips` (List of String) The floating IP of each server that has one, in server order (several with `scale_factor` above 1). With one server, the same as `public_ip`. A server without one (released in the console, or added by autoscaling) gets one on the next apply while `floating_ip_pool` is set.
- `status` (String) The instance's status, for example `running`.

## Import

Import is supported using the following syntax:

```shell
# By the instance's ID. Import adopts the instance; it never creates or deletes it.
terraform import mtncloud_instance_settings.db 9701
```
