# mtncloud_smb_share

An SMB file share, ordered from MTN Cloud's catalog (MTN SMB). Quota and client changes are ordered as updates; destroy orders its deletion. MTN Cloud doesn't report a share's settings back, so changes made in the console aren't seen.

## Example Usage

```terraform
variable "share_password" {
  type      = string
  sensitive = true
}

resource "mtncloud_smb_share" "files" {
  name             = "team-files"
  quota_gb         = 100
  client_ips       = ["10.0.0.0/24"]
  password         = var.share_password
  password_version = 1 # change it to send a new password
}
```

## Schema

### Required

- `name` (String) Share (volume) name. Changing it makes a new share.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `client_ips` (List of String) Addresses allowed to mount the share. Left out or empty, every address may. Changing it updates the share in place.
- `password` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Password of the share's user. Write-only (Terraform 1.11 or newer): never stored. To change it, change `password_version` too.
- `password_version` (Number) Any number; changing it sends `password` again. Write-only values can't be compared, so this is how a new password is noticed.
- `quota_gb` (Number) Size limit in GB. Defaults to 10. Changing it updates the share in place.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

## Import

Import is supported using the following syntax:

```shell
# Imported by the ID of its catalog order (Catalog > Inventory).
terraform import mtncloud_smb_share.files 9801
```

Write the share's settings exactly as they are: the first apply after an import records them and orders nothing.

## Notes

- Create, update and destroy are each an order of the same catalog item: changing `quota_gb` or
  `client_ips` (or `password_version` for SMB) orders an update, and destroy orders the deletion.
- MTN Cloud has no API that reads a share back, so changes made outside Terraform aren't seen.
- Secrets are write-only (Terraform 1.11 or newer): never stored in state.
