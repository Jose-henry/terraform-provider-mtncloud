# mtncloud_app_settings

Settings of an app this configuration doesn't own: a managed service's or self-managed Kubernetes order's app, or one made in the console. Create adopts the app by `app_id` and changes only the settings you set; settings you leave out aren't managed and show the app's own values. **Destroy leaves the app**: it only stops managing these settings. An order keeps its app by ID (`app_id` on the order), so renaming it here doesn't stop the order's destroy from finding it. Add instances to an app with `mtncloud_app_instance`. VMs are resized, powered and given disks through their instances (`mtncloud_instance_settings`): an app has no such settings of its own.

## Example Usage

```terraform
resource "mtncloud_self_managed_kubernetes" "k8s" {
  name                    = "apps-k8s"
  project                 = "web-prod"
  master_plan             = "G2S4"
  master_root_volume_size = 50
  master_networks         = ["app-net"]
  master_security_groups  = ["web"]
  worker_plan             = "G4S16"
  worker_root_volume_size = 100
  worker_networks         = ["app-net"]
  worker_security_groups  = ["web"]
  worker_count            = 3
}

# The order owns the app; these settings manage its name, labels and environment day to day.
resource "mtncloud_app_settings" "k8s" {
  app_id      = mtncloud_self_managed_kubernetes.k8s.app_id
  description = "Shop platform cluster"
  labels      = ["shop", "kubernetes"]
  environment = "Production"
}

# Each of the app's VMs (masters and workers) gets the same day-2 settings, one resource per VM.
# A VM added to the app later is covered once the order's instance_ids shows it.
resource "mtncloud_instance_settings" "node" {
  for_each        = toset(mtncloud_self_managed_kubernetes.k8s.instance_ids)
  instance_id     = each.value
  labels          = ["shop", "kubernetes"]
  security_groups = ["web"]
}
```

## Notes

- **Ownership.** The order or console that made the app still owns it: destroying the order deletes the
  app, and these settings leave state on the next refresh. Renaming the app here doesn't stop the order
  finding it: the order keeps its app by ID.
- **Owner.** Changing `owner` also changes the owner of every instance in the app.
- **Settings left out** aren't managed: they show the app's values, and removing one from the
  configuration leaves the app as it is.
- **VM settings** (plan, power, security groups, labels, tags) belong to each instance: give every VM of the
  app its own `mtncloud_instance_settings` with `for_each` over the order's `instance_ids`, as in the example.
  One resource per VM keeps each VM's state, errors and plan lines apart, and a VM that needs other
  settings (for example a bigger plan for workers) gets its own resource; never manage one VM from two
  resources. Checked live on a self-managed Kubernetes order (master and worker, 2026-10-31).

## Schema

### Required

- `app_id` (String) ID of the app, for example a managed service order's `app_id`. Changing it adopts another app.

### Optional

- `description` (String) Description, changed in place.
- `environment` (String) Environment by name or code, for example `Dev`. Changed in place.
- `labels` (Set of String) Labels. Set, they replace the app's labels in place; `[]` clears them.
- `name` (String) The app's name, changed in place. The order that made it keeps finding it by ID.
- `owner` (String) Owner's username in your tenant. **Changing it also changes the owner of every instance in the app**, which changes who can see and manage them.

### Read-Only

- `group` (String) The app's group, read only.
- `id` (String) The app's ID.
- `instance_ids` (Set of String) IDs of the instances in the app.
- `status` (String) The app's status, for example `running`.

## Import

Import is supported using the following syntax:

```shell
# By the app's ID. Import adopts the app; it never creates or deletes it.
terraform import mtncloud_app_settings.k8s 9901
```
