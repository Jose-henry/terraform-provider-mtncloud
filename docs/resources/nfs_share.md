# mtncloud_nfs_share

An NFS file share, ordered from MTN Cloud's catalog (MTN NFS). Quota and client changes are ordered as updates; destroy orders its deletion. MTN Cloud doesn't report a share's settings back, so changes made in the console aren't seen.

## Example Usage

```terraform
resource "mtncloud_nfs_share" "data" {
  name       = "app-data"
  quota_gb   = 50
  client_ips = ["10.0.0.10", "10.0.0.11"]
}
```

## Import

Import is supported using the following syntax:

```shell
# Imported by the ID of its catalog order (Catalog > Inventory).
terraform import mtncloud_nfs_share.data 9801
```

Write the share's settings exactly as they are: the first apply after an import records them and orders nothing.

## Notes

- Create, update and destroy are each an order of the same catalog item: changing `quota_gb` or
  `client_ips` (or `password_version` for SMB) orders an update, and destroy orders the deletion.
- MTN Cloud has no API that reads a share back, so changes made outside Terraform aren't seen.
- Secrets are write-only (Terraform 1.11 or newer): never stored in state.
