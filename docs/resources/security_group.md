# mtncloud_security_group

A security group (firewall) for instances in one project. OpenStack adds two rules to every new group that allow all outbound traffic (IPv4 and IPv6); they appear in MTN Cloud after its next sync. By default Terraform leaves them in place; set `remove_default_egress` to remove them.

## Example Usage

```terraform
# Rules managed on the group. The two default egress rules (allow all outbound traffic)
# stay in place and are listed in all_rules once MTN Cloud has synced them.
resource "mtncloud_security_group" "web" {
  name        = "web"
  description = "Web servers"
  project     = "web-prod"

  rules = [
    { direction = "ingress", protocol = "tcp", port_range = "443", cidr = "0.0.0.0/0", description = "https" },
    { direction = "ingress", protocol = "tcp", port_range = "22", cidr = "10.0.0.0/24", description = "ssh from admin" },
    { direction = "ingress", protocol = "icmp", cidr = "10.0.0.0/16" },
  ]
}

# Outbound traffic limited to what is listed, once the default egress rules are gone.
# OpenStack adds them at create; MTN Cloud shows them after its sync, and the first apply
# after that removes them. Until then this group still allows all outbound traffic.
resource "mtncloud_security_group" "db" {
  name                  = "db"
  project               = "web-prod"
  remove_default_egress = true

  rules = [
    { direction = "ingress", protocol = "tcp", port_range = "5432", source_security_group_id = mtncloud_security_group.web.id },
    { direction = "egress", protocol = "udp", port_range = "53", cidr = "10.0.0.0/16" },
  ]
}

# Every rule on the group, defaults included.
output "web_rules" {
  value = mtncloud_security_group.web.all_rules
}
```

## Schema

### Required

- `name` (String) Name of the security group.
- `project` (String) Project the group is created in, by name (for example `web-prod`; the full name with the tenant suffix also works). Changing it to another project replaces the group.

### Optional

- `description` (String) Description of the security group.
- `remove_default_egress` (Boolean) Remove the two default egress rules (allow all outbound traffic). Defaults to `false`. OpenStack adds them when the group is created, but MTN Cloud only shows them after its sync, some time later; they are removed by the first `terraform apply` after that (`terraform plan` shows the pending change). **Until then the group allows all outbound traffic.**
- `rules` (Attributes Set) The rules Terraform manages. When set, rules added outside Terraform are removed on the next apply, except the default egress rules (see `remove_default_egress`). Leave it out to let Terraform ignore the rules, for example when they are managed with `mtncloud_security_group_rule`; never use both on one group. (see [below for nested schema](#nestedatt--rules))

### Read-Only

- `all_rules` (Attributes List) Every rule on the group, including the default egress rules and rules managed elsewhere, sorted. Read-only: use it to see the group's complete rule set. (see [below for nested schema](#nestedatt--all_rules))
- `external_id` (String) OpenStack (Neutron) security group ID.
- `id` (String) Security group ID.

### Nested Schema for `rules`

Required:

- `direction` (String) `ingress` (traffic to the instances) or `egress` (traffic from them).
- `protocol` (String) `tcp`, `udp`, `icmp` or `any`.

Optional:

- `cidr` (String) The remote addresses, written as a network (`"10.0.0.0/24"`, `"0.0.0.0/0"`): where traffic comes from for `ingress`, where it goes for `egress`. Leave it and `source_security_group_id` out to allow any address.

- `port_range` (String) A port (`"22"`) or a range (`"8000-8080"`), for `tcp` and `udp`. Leave it out to allow every port.

## Import

Import is supported using the following syntax:

```shell
terraform import mtncloud_security_group.web 9501
```

An imported group adopts every rule it has (except the default egress rules) into `rules`. Write
them all in the configuration, with the descriptions shown in the console, and the first plan after
import is empty. If the configuration leaves `rules` out, that first plan shows `rules` going to
null: an update that changes nothing on MTN Cloud and stops Terraform managing the rules.

## Notes

- **Default egress rules.** OpenStack adds two allow-all outbound rules (IPv4 `0.0.0.0/0` and IPv6
  `::/0`) to every new group. MTN Cloud shows them only after its next sync with OpenStack, which can
  take a while; Terraform never waits for it. They are listed in `all_rules` with `default = true`
  and never counted as drift. With `remove_default_egress = true`, the first `terraform apply`
  after they appear removes them (until then, `terraform plan` shows that pending change).
  **Until that apply, the group allows all outbound traffic**, even though the plan right after
  creating it is empty.
- **Names are unique per project.** Creating a group whose name is already used in the project
  fails and tells you its ID, so you can import it instead. Terraform never takes over a group it
  didn't create.
- **Rules can't be edited in place.** Changing any field of a rule deletes it and adds the new one,
  in one apply.
- **`rules` or `mtncloud_security_group_rule`, not both** on the same group: each would remove the
  other's rules.
- **Project.** Short (`web-prod`) and full (`web-prod-<tenant>`) names are the same project. Moving a
  group to another project replaces it.
- **Deleting** a group still attached to instances fails: detach it first.
