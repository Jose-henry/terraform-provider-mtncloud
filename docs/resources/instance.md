# mtncloud_instance

An MTN Cloud instance: an OpenStack virtual machine in one of your projects. Creating it waits until MTN Cloud reports it running, usually a few minutes. The project's default security group is always applied, as MTN Cloud requires.

## Example Usage

```terraform
resource "mtncloud_network" "app" {
  name    = "app-net"
  project = "web-prod"
  cidr    = "10.20.1.0/24"
  gateway = "10.20.1.1"
}

resource "mtncloud_security_group" "web" {
  name    = "web"
  project = "web-prod"

  rules = [
    { direction = "ingress", protocol = "tcp", port_range = "443", cidr = "0.0.0.0/0" },
  ]
}

resource "mtncloud_instance" "web" {
  name     = "web-1" # leave out to use your tenant's naming template
  group    = "MTNNG_CLOUD_AZ_1"
  project  = "web-prod"
  image    = "MTN Ubuntu Server 24.04.3LTS"
  plan     = "G2S4"
  networks = [mtncloud_network.app.id]

  # The project's default security group is always applied as well.
  security_groups = [mtncloud_security_group.web.name]

  root_volume_size = 40
  data_volume {
    size      = 100
    datastore = "ENCR_AT_REST"
  }

  environment = "Production"
  labels      = ["web"]
  tags = {
    team = "payments"
  }
}
```

Several identical instances: use `count` or `for_each`, and leave `name` out so the naming template
numbers them, or set it from the key.

```terraform
resource "mtncloud_instance" "worker" {
  for_each = toset(["a", "b", "c"])

  name     = "worker-${each.key}"
  group    = "MTNNG_CLOUD_AZ_1"
  project  = "web-prod"
  image    = "MTN-U24.04LTS"
  plan     = "G1S1"
  networks = [mtncloud_network.app.id]
}
```

## Schema

### Required

- `group` (String) Group the instance is provisioned into, by name, for example `MTNNG_CLOUD_AZ_1`. Changing it replaces the instance.
- `image` (String) Operating system image, by name (`MTN Ubuntu Server 24.04.3LTS`) or code (`MTN-U24.04LTS`); the `mtncloud_images` data source lists them. Changing it replaces the instance.
- `networks` (List of String) IDs of the MTN Networks to connect, for example `[mtncloud_network.app.id]`. The first is the primary network: changing it replaces the instance. Networks added at the end are attached in place (the guest OS must configure the new card); removing or reordering networks replaces the instance.
- `plan` (String) Size of the VM, for example `G2S4` (the `mtncloud_plans` data source lists a project's sizes). **Changing it restarts the VM**, in place.
- `project` (String) Project the instance runs in, by name (for example `web-prod`; the full name with the tenant suffix also works). Changing it to another project replaces the instance.

### Optional

- `create_user` (Boolean) Create your user (from your Linux or Windows user settings) on the VM. Defaults to `true`. Changing it replaces the instance.
- `data_volume` (Block List) Extra disks, in order. Volumes added at the end are attached in place; changing or removing one replaces the instance. (see [below for nested schema](#nestedblock--data_volume))
- `datastore` (String) Datastore of the root volume, by name, for example `ENCR_AT_REST` (the `mtncloud_datastores` data source lists them). Left out, the project's default. Changing it replaces the instance.
- `description` (String) Description of the instance.
- `domain` (String) Network domain the instance joins, by name, for example `example.com`. Left out, MTN Cloud may apply the network's domain, shown here. Changing it replaces the instance.
- `env_vars` (Map of String, Sensitive) Environment variables for the instance's automation, name to value. Sensitive: values are hidden in plans, but stored in state. The variables MTN Cloud adds itself (address, host, ports) are not shown. Changing them replaces the instance.
- `environment` (String) Environment, by name or code, for example `Production`. Changed in place.
- `hostname` (String) Hostname set inside the VM. Left out, MTN Cloud derives it from the name or your hostname template. Changing it replaces the instance.
- `install_agent` (Boolean) Install the MTN Cloud agent, for monitoring, logs and automation. Defaults to `true`. The agent needs the network to be on an MTN Router. Changing it replaces the instance.
- `labels` (Set of String) Labels (keywords). Changed in place.
- `name` (String) Name of the instance. Leave it out to use your tenant's naming template (for example `<initials>-<account>-MTN-CLOUD-<type>-<n>`); the generated name is then shown here. Renaming is done in place.
- `root_volume_size` (Number) Root volume size in GB. Left out, the plan's size applies (10 GB). MTN Cloud can't resize a root volume: add a `data_volume` instead. Windows images need at least 40 GB.
- `scale_factor` (Number) Number of VMs in the instance. Defaults to 1. For several separate instances use `count` or `for_each`. Changing it replaces the instance.
- `security_groups` (Set of String) Security groups to apply, by name, in addition to the project's default group, which is always applied. Changed in place. Each group needs the project as a location.
- `tags` (Map of String) Metadata tags, name to value. Changed in place.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `private_ip` (String) Private IP address on the primary network.
- `public_ip` (String) Floating (public) IP address, when the instance has one.

## Import

Import is supported using the following syntax:

```shell
terraform import mtncloud_instance.web 9701
```

Write the project's short name (`web-prod`) and the image as the console shows it, and the first
plan after import is empty. `create_user` can't be read back and is taken as `true`.

## Notes

- **Waits until running.** A new instance is "provisioning" for a few minutes; create and update
  wait until MTN Cloud reports it running (default timeout 30 minutes, see `timeouts`). An instance
  that ends "failed" or "error" (then or later) is reported with MTN Cloud's reason, kept in state,
  and replaced by the next apply.
- **Restarts the VM:** changing `plan`. `status` and `public_ip` are read again after any update.
- **Changes in place:** `name`, `description`, `environment`, `labels`, `tags`, `security_groups`,
  `plan`, networks added at the end of `networks`, and volumes added at the end of `data_volume`.
- **Replaces the instance:** `group`, `project`, `image`, `hostname`, `datastore`, `domain`,
  `env_vars`, `install_agent`, `create_user`, `scale_factor`, the primary (first) network, and
  removing, reordering or changing existing networks or data volumes.
- **Refused at plan time:** a new `root_volume_size` (MTN Cloud can't resize a root volume), a
  Windows image with a root volume under 40 GB, and any name (plan, security group, datastore,
  environment, domain) the project doesn't have; the error lists the valid ones.
- **Default security group.** The project's default security group is always applied, as MTN
  Cloud requires. It shows in `security_groups` only if you list it.
- **Names.** With `name` set, an instance of that name already in the project is refused with its
  ID, so you can import it instead. Left out, your tenant's naming template names the instance.
- **Values known only at apply.** If `group`, `project` or `image` comes from a resource created in
  the same apply, Terraform can't tell whether it changed, so the plan replaces the instance.
- **`env_vars` are sensitive:** hidden in plan output, but stored in state like every attribute.
- **Floating IPs** are not managed by this resource yet. A floating IP attached in the console shows
  in `public_ip`.
