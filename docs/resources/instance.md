# mtncloud_instance

An MTN Cloud instance: a virtual machine in one of your projects. Creating it waits until MTN Cloud reports it running, usually a few minutes. The project's default security group is always applied, as MTN Cloud requires.

## Example Usage

```terraform
resource "mtncloud_network" "app" {
  name    = "app-net"
  project = "web-prod"
  cidr    = "10.20.1.0/24"
  gateway = "10.20.1.1"
}

resource "mtncloud_security_group" "web" {
  name    = "web"
  project = "web-prod"

  rules = [
    { direction = "ingress", protocol = "tcp", port_range = "443", cidr = "0.0.0.0/0" },
  ]
}

resource "mtncloud_instance" "web" {
  name     = "web-1" # leave out to use your tenant's naming template
  group    = "MTNNG_CLOUD_AZ_1"
  project  = "web-prod"
  image    = "MTN Ubuntu Server 24.04.3LTS"
  plan     = "G2S4"
  networks = [mtncloud_network.app.id]

  # The project's default security group is always applied as well.
  security_groups = [mtncloud_security_group.web.name]

  # A public IP, once the VM runs. The network must be on an MTN Router with an external network.
  floating_ip_pool = "public-network-02"

  root_volume_size = 40
  data_volume {
    size      = 100
    datastore = "__DEFAULT__"
  }

  # Add a VM above 75% CPU, remove one below 30%, between 1 and 3 VMs.
  scale = {
    min_count = 1
    max_count = 3
    cpu       = { min = 30, max = 75 }
  }

  # Power the VM on or off in place ("running", "stopped" or "suspended").
  power_state = "running"
  # Change this to any new value to reboot the VM on the next apply.
  restart_trigger = "2026-10-28"

  environment = "Production"
  labels      = ["web"]
  tags = {
    team = "payments"
  }
}
```

Several identical instances: use `count` or `for_each`, and leave `name` out so the naming template
numbers them, or set it from the key.

```terraform
resource "mtncloud_instance" "worker" {
  for_each = toset(["a", "b", "c"])

  name     = "worker-${each.key}"
  group    = "MTNNG_CLOUD_AZ_1"
  project  = "web-prod"
  image    = "MTN-U24.04LTS"
  plan     = "G1S1"
  networks = [mtncloud_network.app.id]
}
```

## Schema

### Required

- `image` (String) Operating system image, by name (`MTN Ubuntu Server 24.04.3LTS`) or code (`MTN-U24.04LTS`); the `mtncloud_images` data source lists them. Changing it replaces the instance.
- `networks` (List of String) IDs of the MTN Networks to connect, for example `[mtncloud_network.app.id]`. The first is the primary network. Any change replaces the instance: MTN Cloud doesn't report an instance's network card IDs, so a network can't be added to a running instance safely.
- `plan` (String) Size of the VM, for example `G2S4` (the `mtncloud_plans` data source lists a project's sizes). **Changing it restarts the VM**, in place.

### Optional

- `create_user` (Boolean) Create your user (from your Linux or Windows user settings) on the VM. Defaults to `true`. Changing it replaces the instance.
- `data_volume` (Block List) Extra disks, in order. Volumes added at the end are attached in place; changing or removing one replaces the instance. (see [below for nested schema](#nestedblock--data_volume))
- `datastore` (String) Datastore of the root volume, by name, for example `__DEFAULT__` (the `mtncloud_datastores` data source lists them). Left out, the project's default. Changing it replaces the instance.
- `description` (String) Description of the instance.
- `domain` (String) Network domain the instance joins, by name, for example `example.com`. Left out, MTN Cloud may apply the network's domain, shown here. Changing it replaces the instance.
- `env_vars` (Map of String, Sensitive) Environment variables for the instance's automation, name to value. Sensitive: values are hidden in plans, but stored in state. The variables MTN Cloud adds itself (address, host, ports) are not shown. Changing them replaces the instance.
- `environment` (String) Environment, by name or code, for example `Production`. Changed in place.
- `expire_days` (Number) Delete the instance this many days after it is created. Set at create only: afterwards extend or cancel the expiry in the console (a change here is refused at plan time).
- `floating_ip_pool` (String) Give the instance a floating (public) IP from this pool, for example `public-network-02` (the `mtncloud_external_networks` data source lists the names). It is attached once the VM is running, and works only when the instance's network is on an MTN Router with an external network. Changed in place: the old address is released and a new one attached. Apply waits until the instance shows the address (in `public_ip`), and fails if it doesn't.
- `group` (String) Group the instance is provisioned into, by name, for example `MTNNG_CLOUD_AZ_1`. Defaults to the provider's `group`. Changing it, or that default when you rely on it, replaces the instance.
- `hostname` (String) Hostname set inside the VM. Left out, MTN Cloud derives it from the name or your hostname template. Changing it replaces the instance.
- `install_agent` (Boolean) Install the MTN Cloud agent, for monitoring, logs and automation. Defaults to `true`. The agent needs the primary network to be on an MTN Router with an external network, so it can reach MTN Cloud: without one, the VM stays "provisioning" (finalizing) until the create timeout. Changing it replaces the instance.
- `labels` (Set of String) Labels (keywords). Changed in place.
- `name` (String) Name of the instance. Leave it out to use your tenant's naming template (for example `<initials>-<account>-MTN-CLOUD-<type>-<n>`); the generated name is then shown here. Renaming is done in place.
- `power_state` (String) `running`, `stopped` or `suspended`. Set it to power the VM on, off, or suspend it, in place: stopping shuts the server down and keeps its disks and addresses. When set, a VM started or stopped in the console is put back by the next apply. Left out, the VM's power isn't managed and this shows its state. A plan change or added volume restarts the VM, then it is put back in this state.
- `project` (String) Project the instance runs in, by name (for example `web-prod`; the full name with the tenant suffix also works). Defaults to the provider's `project`. Changing it to another project, or that default when you rely on it, replaces the instance.
- `restart_trigger` (String) Any value; changing it to a new value restarts the VM (server reboot) in place on the next apply, for example `restart_trigger = timestamp()` or a version string. Nothing happens at create, when it is removed, or while `power_state` is `stopped` or `suspended`.
- `root_volume_size` (Number) Root volume size in GB. Left out, the plan's size applies (10 GB). MTN Cloud can't resize a root volume: add a `data_volume` instead. Windows images need at least 40 GB.
- `scale` (Attributes) Automatic scaling: MTN Cloud adds a VM when usage stays above a metric's `max` and removes one below its `min`, between `min_count` and `max_count`. Watch at least one of `cpu`, `memory`, `disk`. Changed in place; removing it turns scaling off. (see [below for nested schema](#nestedatt--scale))
- `scale_factor` (Number) Number of VMs in the instance. Defaults to 1. For several separate instances use `count` or `for_each`. Changing it replaces the instance.
- `security_groups` (Set of String) Security groups to apply, by name, in addition to the project's default group, which is always applied; listing the default too changes nothing. Changed in place. Each group needs the project as a location.
- `shutdown_days` (Number) Stop the VM this many days after it is created. Set at create only, like `expire_days`.
- `tags` (Map of String) Metadata tags, name to value. Changed in place.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

## Import

Import is supported using the following syntax:

```shell
terraform import mtncloud_instance.web 9701
```

Write the project's short name (`web-prod`) and the image as the console shows it, and the first
plan after import is empty. `create_user` can't be read back and is taken as `true`.

## Notes

- **Waits until running.** A new instance is "provisioning" for a few minutes; create and update
  wait until MTN Cloud reports it running (default timeout 30 minutes, see `timeouts`). An instance
  that ends "failed" or "error" (then or later) is reported with MTN Cloud's reason, kept in state,
  and replaced by the next apply. With `install_agent` on (the default), the VM is only "running"
  once its agent reports in, so its primary network must be on an MTN Router with an external network:
  on an isolated network it stays "provisioning" until the timeout. Expect 10 to 30 minutes.
- **Restarts the VM:** changing `plan`, or a new `restart_trigger`. `status` and `public_ip` are
  read again after any update.
- **Power.** Set `power_state` to `running`, `stopped` or `suspended` to power the VM on, off or into
  suspend in place; a VM changed in the console is put back by the next apply. Left out, power isn't
  managed, and `power_state` shows the VM's state. A plan change starts a stopped VM, then it is put
  back in the `power_state` you set. To reboot, change `restart_trigger` to any new value. A power
  change the VM doesn't start within 2 minutes fails the apply (MTN Cloud accepts a suspend some VMs
  don't support); use `stopped` for those.
- **Changes in place:** `name`, `description`, `environment`, `labels`, `tags`, `security_groups`, `scale`,
  `floating_ip_pool`, `power_state`, `restart_trigger`,
  `plan`, and volumes added at the end of `data_volume`.
- **Replaces the instance:** `group`, `project`, `image`, `hostname`, `datastore`, `domain`,
  `env_vars`, `install_agent`, `create_user`, `scale_factor`, any change to `networks`, and
  removing, reordering or changing existing data volumes.
- **Set at create only:** `expire_days` and `shutdown_days`. Changing them later is refused at plan
  time; extend or cancel an expiry in the console. `expire_date` and `shutdown_date` show the dates,
  including ones a policy sets.
- **Refused at plan time:** a new `root_volume_size` (MTN Cloud can't resize a root volume), a
  Windows image with a root volume under 40 GB, and any name (plan, security group, datastore,
  environment, domain) the project doesn't have; the error lists the valid ones.
- **Default security group.** The project's default security group is always applied, as MTN
  Cloud requires. It shows in `security_groups` only if you list it.
- **Names.** With `name` set, an instance of that name already in the project is refused with its
  ID, so you can import it instead. Left out, your tenant's naming template names the instance.
- **Values known only at apply.** If `group`, `project` or `image` comes from a resource created in
  the same apply, Terraform can't tell whether it changed, so the plan replaces the instance.
- **`env_vars` are sensitive:** hidden in plan output, but stored in state like every attribute.
- **Workflows and deployments** aren't managed by this resource yet. MTN's workflows are operations
  you run on an existing instance from the console.
- **Floating IP.** `floating_ip_pool` attaches a public address once the VM is running (never in the
  create request), and the apply waits until the instance shows it in `public_ip`. If the attach
  fails, or the address doesn't show before the timeout, that apply fails. At create, Terraform then
  marks the instance tainted, so the next apply replaces it; run `terraform untaint` to keep the VM
  and try the attach again. It needs the instance's network to be on an `mtncloud_router` with an
  `external_network`; reference the router (for example in `depends_on`) so it exists first. The plan
  checks this: a router on another external network is an error naming the pool to use, and no router
  at all is a warning (the router may come in the same apply).
  Changing the pool releases the old address and attaches a new one, waiting for each. An address
  released in the console is attached again by the next apply. A floating IP attached in the console,
  with no `floating_ip_pool` set, shows in `public_ip` and is left alone; setting `floating_ip_pool`
  later (or after an import) adopts that address without attaching another. If an attach was sent but
  its address never showed before the timeout, it isn't sent again (that could attach a second
  address); a warning says so on each plan until it appears. With `scale_factor` above 1, an attach is
  sent for each VM, but the wait and the drift check look at the instance as a whole, so check each
  VM's address in the console.
