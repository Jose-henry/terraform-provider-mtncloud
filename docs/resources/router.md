# mtncloud_router

An MTN Router: connects MTN Networks of one project to each other and, through an external network, to the outside. Creating it waits until MTN Cloud reports it ready, usually within seconds.

## Example Usage

```terraform
resource "mtncloud_network" "app" {
  name    = "app-net"
  project = "web-prod"
  cidr    = "10.20.1.0/24"
  gateway = "10.20.1.1"
}

resource "mtncloud_network" "db" {
  name    = "db-net"
  project = "web-prod"
  cidr    = "10.20.2.0/24"
  gateway = "10.20.2.1"
}

# Connects both networks, and gives them a way out through a public network.
resource "mtncloud_router" "edge" {
  name             = "edge"
  project          = "web-prod"
  networks         = [mtncloud_network.app.id, mtncloud_network.db.id]
  external_network = "public-network-02"
}

output "edge_external_ip" {
  value = mtncloud_router.edge.external_ip
}
```

To attach a network made outside Terraform, look it up by name:

```terraform
data "mtncloud_network" "legacy" {
  name = "legacy-net"
}

resource "mtncloud_router" "edge" {
  name     = "edge"
  project  = "web-prod"
  networks = [data.mtncloud_network.legacy.id]
}
```

## Schema

### Required

- `name` (String) Name of the router. MTN Cloud doesn't allow renaming a router: a new name replaces it.
- `networks` (Set of String) IDs of the MTN Networks the router connects, for example `[mtncloud_network.app.id]`. Networks are added and removed in place. Use the `mtncloud_network` data source for networks made outside Terraform.
- `project` (String) Project the router is created in, by name (for example `web-prod`; the full name with the tenant suffix also works). Its networks must be in the same project. Changing it to another project replaces the router.

### Optional

- `description` (String) Description of the router.
- `enabled` (Boolean) Whether the router is enabled. Defaults to `true`.
- `external_network` (String) External network that gives the router its gateway and external IP, by name, for example `public-network-02`. Changing it moves the gateway in place, and the external IP changes. Leave it out for a router that only connects your networks.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `external_id` (String) Router ID in the cloud (the external ID).
- `external_ip` (String) The router's address on the external network. Empty without `external_network`.
- `id` (String) Router ID.

## Import

Import is supported using the following syntax:

```shell
terraform import mtncloud_router.edge 9601
```

MTN Cloud doesn't report which project a router is in, so import takes it from the router's first
network (a router without networks takes the project from the configuration). Write the project's short name (`web-prod`) in the configuration to keep the first plan empty.

## Notes

- **Waits until ready.** A new router is "provisioning" for a few seconds; create and update wait
  for MTN Cloud to report it ready (default timeout 10 minutes, see `timeouts`). A router that fails
  is reported with MTN Cloud's status and replaced by the next apply.
- **Can't change in place:** `name` (MTN Cloud refuses renames) and `project`. Each replaces the router.
- **Changes in place:** `networks` (attach or detach), `external_network` (the external IP changes
  with it; removing it removes the gateway), `description` and `enabled`.
- **One project.** Every network must be in the router's project; another project's network is
  refused before anything is sent.
- **Order.** Because `networks` references the networks, Terraform creates them first and deletes the
  router first, so a network is never deleted while the router still holds a port on it.
- **Names are unique per project.** Creating a router whose name is already used in the project
  fails and gives its ID, so you can import it instead.
