# mtncloud_managed_kubernetes

A Kubernetes cluster that MTN Cloud installs and manages. Ordered from MTN Cloud's catalog (MTN KUBERNETES (MK8S)). The order's inputs can't be changed afterwards, and `terraform destroy` refuses: delete what it made in the console, under Instances, then remove the resource from state. Secrets are write-only (Terraform 1.11 or newer): they are sent with the order and never stored.

## Example Usage

```terraform
resource "mtncloud_managed_kubernetes" "k8s" {
  name                    = "apps-k8s"
  project                 = "web-prod"
  master_plan             = "G2S4"
  master_root_volume_size = 50
  master_networks         = ["app-net"]
  master_security_groups  = ["web"]
  master_count            = 3
  worker_plan             = "G4S16"
  worker_root_volume_size = 100
  worker_networks         = ["app-net"]
  worker_security_groups  = ["web"]
  worker_count            = 3
  cni                     = "calico"
}
```

## Import

Import is supported using the following syntax:

```shell
# Imported by the ID of its catalog order (Catalog > Inventory).
terraform import mtncloud_managed_kubernetes.k8s 9801
```

The order doesn't show what it was placed with, so the inputs come from your configuration: write them
exactly as ordered. The first apply after an import records them, finds the instances by name, and orders nothing.

## Notes

- **An order, not a live object.** Create places the catalog order and waits for MTN's workflow to
  finish, then finds the instances it made by `name` in the project (`instance_ids`). The inputs
  can't be changed afterwards: the plan refuses, so nothing is ever ordered twice by accident.
- **Destroy refuses.** Delete what the order made in the console (under Instances), then stop managing it
  with a `removed` block (`lifecycle { destroy = false }`) or `terraform state rm`. If everything it
  made is deleted, the next plan orders it again.
- **Secrets are write-only** (Terraform 1.11 or newer): they are sent with the order and never stored
  in state or plans.
- **Names are checked when you plan**: project, plan, networks, security groups, floating IP pool,
  environment and every choice list (versions and so on) are looked up in MTN Cloud before anything
  is ordered, and an unknown value lists the valid ones.
- **A failed workflow** is reported with MTN Cloud's message and nothing is kept; delete whatever it
  left in the console before applying again.
