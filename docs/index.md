# MTN Cloud Provider

Use the MTN Cloud provider to manage [MTN Cloud](https://console.cloud.mtn.ng) with Terraform:
instances, MTN Networks and MTN Routers, security groups, and the platform's catalog, automation and
access settings. You pick things by name (projects, images, plans, security groups), and the
provider checks those names when you run `terraform plan`, before anything is created.

`terraform plan` only reads from MTN Cloud. Nothing is created, changed or deleted until you run
`terraform apply` and confirm.

The [features guide](guides/features.md) lists every resource and data source, and which ones a
customer (sub-tenant) login can use. Use the navigation on the left for each one's documentation.

## Authentication

The provider signs in with a username and password, or an API token:

* [Static credentials](guides/auth.md#static-credentials)
* [Environment variables](guides/auth.md#environment-variables)
* [Configuring the provider: every way to set it up](guides/configuration.md) (credentials, group, cloud and project, variables and files)

A customer login also needs your tenant's subdomain or account ID, set with `tenant_subdomain` or `MTNCLOUD_API_TENANT`.

**Long applies.** Some orders take longer than an API token lasts: a SOPHOS firewall about an hour, a
Kubernetes cluster often more than 25 minutes. A token that expires mid-apply fails it with a 401
while the order goes on in MTN Cloud. For those applies, sign in with a username and password (the
provider signs in again when its token expires), use a token that lasts longer than the apply, or use
`access_token_file` (`MTNCLOUD_API_TOKEN_FILE`): the provider reads the file again when a token is
refused, so a token refreshed in that file during the apply is picked up. The tenancy, IAM,
integration, automation, policy and appliance-configuration resources read it once, when the run
starts: keep long orders and those resources in separate applies.

TLS certificates are verified by default. Set `secure = false` (or `MTNCLOUD_API_SECURE=false`) only
for a console with a self-signed certificate, never in production.

## Defaults for project, group and cloud

Set `project` (and `group`) once on the provider block, or with `MTNCLOUD_PROJECT` and
`MTNCLOUD_GROUP`, and leave them out of `mtncloud_instance`, `mtncloud_network`, `mtncloud_router`
and `mtncloud_security_group`. A value on the resource always wins. With neither set, the plan
fails and names the attribute.

`group` and `cloud` also choose the group and cloud when your account has several, for example for
`mtncloud_project`. With one of each, you don't need them.

State records the project each resource was created in. If you later change the provider's
`project`, resources that rely on it show as **replaced** in the plan: read the plan before
applying. Data source filters never use these defaults: a list with no `project` lists every
project.

## Example Usage

```terraform
terraform {
  required_providers {
    mtncloud = {
      source  = "jose-henry/mtncloud"
      version = "~> 0.7"
    }
  }
}

provider "mtncloud" {
  url      = var.mtncloud_url
  username = var.mtncloud_username
  password = var.mtncloud_password

  # Optional defaults: resources that leave out project (or group) use these.
  project = var.mtncloud_project
}
```

### Optional

- `access_token` (String, Sensitive) Access Token of MTN Cloud user. This can be used instead of authenticating with Username and Password.
- `access_token_file` (String) A file holding the access token, read instead of `access_token`. Most resources and data sources read it again when MTN Cloud rejects the token, so a long apply survives a token refreshed in that file; the tenancy, IAM, integration, automation, policy and appliance-configuration ones read it once, when the run starts. Can also be set with the MTNCLOUD_API_TOKEN_FILE environment variable.
- `cloud` (String) The cloud to use when your group has several, by name, for example MTNNG_CLOUD_AZ_1. Can also be set with the MTNCLOUD_CLOUD environment variable.
- `group` (String) Default group, by name, for resources that don't set one, and the group to use when your account has several. Can also be set with the MTNCLOUD_GROUP environment variable.
- `password` (String, Sensitive) Password of MTN Cloud user for authentication
- `project` (String) Default project, by name (for example web-prod), for resources that don't set one. Can also be set with the MTNCLOUD_PROJECT environment variable.
- `secure` (Boolean) Verify the MTN Cloud console's TLS certificate. Defaults to "true". Set to "false" only for a console with a self-signed certificate.
- `tenant_subdomain` (String) Your tenant, for a username login: its subdomain or its numeric account ID (both work).
- `url` (String) The URL of the MTN Cloud console where requests will be directed.
- `username` (String) Username of MTN Cloud user for authentication
