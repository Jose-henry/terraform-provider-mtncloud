# mtncloud_plans (Data Source)

Lists the instance sizes (plans) a project offers for an image, for example `G2S4` (2 vCPU, 4 GB). Each project has its own copy of every size, so plan IDs differ between projects: pick plans by `name`.

## Example Usage

```terraform
# Sizes the "web-prod" project offers for Ubuntu 24.04 with at least 2 vCPUs and 4 GB of memory.
data "mtncloud_plans" "web" {
  project       = "web-prod"
  image         = "MTN Ubuntu Server 24.04.3LTS"
  min_cores     = 2
  min_memory_gb = 4
}

# Plans come back smallest first, so this is the smallest size that fits.
output "smallest_fit" {
  value = data.mtncloud_plans.web.plans[0].name
}
```

## Schema

### Required

- `image` (String) Image the plans are for, by name (for example `MTN Ubuntu Server 24.04.3LTS`, case ignored) or code (`MTN-U24.04LTS`). See `mtncloud_images`.
- `project` (String) Project name, as shown in the console (for example `web-prod`). The full platform name, with the tenant suffix, also works.

### Optional

- `min_cores` (Number) Only return plans with at least this many vCPUs.
- `min_memory_gb` (Number) Only return plans with at least this much memory, in GB.
- `name_regex` (String) Only return plans whose name matches this regular expression (RE2 syntax), for example `^web-`.

### Read-Only

- `plans` (Attributes List) The plans, smallest first (by vCPUs, then memory, then name). (see [below for nested schema](#nestedatt--plans))

### Nested Schema for `plans`

Read-Only:

- `code` (String) Plan code.
- `cores` (Number) vCPUs.
- `id` (Number) Plan ID in this project.
- `memory_gb` (Number) Memory in GB.
- `name` (String) Plan name, for example `G2S4`. Use this to pick a plan.
- `root_disk_gb` (Number) Default root disk size in GB. The root disk can be made larger when the instance is created.
