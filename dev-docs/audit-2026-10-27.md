## Answers

**Identity sources** (`mtncloud_active_directory_identity_source`, `mtncloud_saml_identity_source`).
They let a tenant's own Active Directory, or a SAML single sign-on provider (Azure AD, Okta,
OneLogin...), log users in to MTN Cloud, and map the directory's groups to MTN Cloud roles. They
are per tenant; a customer admin can manage them when MTN's tenant role grants
`Admin: Identity Source` (the test tenant already has two: Active Directory and Okta). **Kept.**

**What a customer does in the Library.** Automation (tasks, workflows), virtual images and
integrations; plus forms, inputs and option lists (owner, 2026-10-27). No instance types, layouts,
node types, cluster layouts, templates, scripts, blueprints, spec templates or catalog items.

Removed: Groovy, JavaScript, Python and jRuby script tasks (the API has them; customers' console
doesn't offer them). The API also lists platform jobs (load balancer diagnostics, managed services):
never exposed.

**Do task types need data sources?** One pair covers every type: `mtncloud_task` (one task by name
or ID) and `mtncloud_tasks` (list, filter by name or type). A data source per type would only
repeat it. Same for workflows (`mtncloud_workflow` + new `mtncloud_workflows`).

**Library Script / Library Template tasks** point at a script or template MTN shares with the
tenant. Customers can't create those, so the task resolves it by name itself; no template data
source is needed.

**Cypher.** Six mounts: `secret` (stores a value or key=value object), `tfvars` (stores a tfvars
file), `password` (generates a password, `password/<length>/<name>`, default 15), `uuid`
(generates a UUID), `key` (generates a base64 AES key, `key/<bits>/<name>`), `vault` (reads/writes
a HashiCorp Vault server; needs MTN to install the Vault plugin). **Lease**: per key, in seconds,
default 32 days (2,764,800); when it ends the key is revoked and a generated value is made again on
the next read. Today `cypher_secret` and `cypher_tfvars` take `key`, `value` and `ttl` (the lease).
Plan: `mtncloud_cypher_password`, `mtncloud_cypher_uuid`, `mtncloud_cypher_key` (generated value,
`Sensitive`, in state: unavoidable to use it), lease on all, `expire_date` shown; data sources
`mtncloud_cypher` (any key; value `Sensitive`) and `mtncloud_cyphers` (keys, leases and expiry
dates, never values). `vault` waits until MTN confirms the plugin is installed.

**Cloud type and provision type data sources.** Catalogues of every cloud technology the platform
supports (AWS, VMware...) and every provisioning engine. Customers never pick one: removed.

## Provider defaults (phase 3)

`group`, `cloud` and `project` on the provider block (and `MTNCLOUD_GROUP`, `MTNCLOUD_CLOUD`,
`MTNCLOUD_PROJECT`). Every resource and data source that takes them makes them optional; the
resource's own value wins, then the provider's, then the environment; none set is a plan-time
error naming the field. State keeps the project used, so a later change of the default shows as a
replacement in the plan (documented). No profile file (owner, 2026-10-27).
