# Terraform provider engineering rules

These are not optional. A PR that breaks one says why in its description.

## Model
1. Design for Terraform's model, not the API's. No `*_json = jsonencode(...)` escape hatches for
   things that can be typed.
2. The resource ID is the server's stable ID: never a name, token or generated value. Composite IDs
   (`<group>/<id>`) are documented and parsed by one helper.
3. Every attribute is deliberately `Required`, `Optional`, `Computed` or `Optional+Computed`. Ask who
   sets it: the user, the API, or both. An `Optional+Computed` attribute gets a comment explaining why.
4. Users pick things by **name or code**, and IDs are resolved at plan time (D-006,
   [catalog-lookups](../../dev-docs/catalog-lookups.md)). Never hard-code a numeric ID in Go.
5. Fields that are immutable in practice use `RequiresReplace` or a plan-time error, never a silent
   API failure. Examples: primary NIC, root disk grow, network CIDR, LB listener protocol/port.
6. Side effects are stated in the attribute description. For example, changing `plan` restarts the VM.

## Diffs and state
7. Zero diff churn. Read normalises case, trailing slashes, CIDR form, port ranges (`22` not
   `22-22`) and server-added suffixes (project `-<TENANCY>`). Use sets where order has no meaning,
   and `UseStateForUnknown` for stable computed values.
8. Read on a 404 removes the resource from state (recreate on drift). It never errors.
9. No secrets in state unless unavoidable. When unavoidable, mark them `Sensitive` and document it.
   Prefer write-only arguments where Terraform supports them.
10. After the first release, a schema change needs a state upgrader, SemVer and a deprecation period.

## Robustness
11. Create is idempotent: after a retry or timeout, look up by name and scope before creating again.
12. Async work (instances, projects, catalog orders, LBs) polls to a terminal state with backoff,
    honours `timeouts {}`, and fails with the platform's own status message.
13. Eventual consistency: a 404 straight after a create is retried, not treated as gone.
14. Retries live only in the client: 429/500/502/503/504 and network timeouts, exponential backoff
    with jitter and a cap. Never retry a 4xx validation error, and never loop with `for {}`.
15. Client-side rate limiting, so `-parallelism=50` can't flood the API.
16. Every call takes `ctx` and stops when it is cancelled.

## UX
17. Validate at plan time: CIDRs, ports 1–65535, enums, name rules, Windows root volume of at least
    40 GB. The API error is the last line of defence.
18. Errors say what went wrong and how to fix it. Map API errors once, in `internal/client`.
19. `terraform import` works from day one for anything that can exist outside Terraform.
20. Log with `tflog` structured fields. Never log credentials or Cypher values.
21. Keep API calls down: use the create/update response instead of re-reading, cache static lookups
    per provider instance, and make one list call per kind per run.

## Docs
22. Every resource and data source has a description, an example, arguments, attributes, import
    syntax, and notes (side effects, master-only, timeouts). Generated by tfplugindocs; CI fails on drift.
23. Master-only resources say so in the first line of their description (D-004).
